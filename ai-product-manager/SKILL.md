# AI 产品经理 — 实战技能

## 概述

本技能定义 AI 产品经理的核心职责与工作方法，聚焦 **Agent 类产品** 的规划、设计、落地与迭代。适合面向 AI / AIGC / 效率工具 / 创作类产品的 PM。

---

## 1. 核心职责

### 1.1 产品规划与迭代
- 负责 Agent 相关产品的路线图规划、需求定义、版本迭代
- 输出 PRD、功能规格文档、交互原型说明
- 定义产品北极星指标与阶段性 OKR

### 1.2 用户需求与场景设计
- 深入理解目标用户在什么场景下需要 AI 帮助
- 设计 Agent 的交互流程、功能机制与产品体验
- 判断一个 AI 功能解决什么问题、适合什么用户、在什么环节介入

### 1.3 跨团队协作
- 与研发团队沟通技术可行性与实现方案
- 与算法团队讨论模型能力边界、Prompt 设计、效果调优
- 与设计团队协作输出交互原型和 UI 规范
- 与运营团队配合制定上线策略与用户增长方案

### 1.4 效果评估与优化
- 建立产品效果评估体系（准确率、完成率、用户满意度等）
- 通过数据埋点、用户访谈、Badcase 回捞持续优化
- 驱动产品从 "能用" 到 "好用" 再到 "爱用"

## 3. AI Agent 产品设计流程

### Phase 1: 需求发现与场景定义

```
[用户痛点] → [AI 能做什么] → [场景价值判断] → [优先级排序]
```

**关键问题清单**：
- 用户在当前流程中最大的卡点是什么？
- AI 介入后能否带来数量级的体验提升？
- 用户是否愿意为这个 AI 能力改变习惯？
- 这个场景的 Badcase 容忍度有多高？

### Phase 2: 交互与功能设计

**Agent 设计要素**：

| 要素 | 说明 | 设计要点 |
|------|------|---------|
| 触发方式 | 用户如何唤起 Agent | 自动/手动/被动触发 |
| 上下文理解 | Agent 能获取哪些信息 | 会话历史/用户画像/实时数据 |
| 输出形式 | Agent 如何呈现结果 | 文本/卡片/图表/可操作按钮 |
| 纠错机制 | Agent 出错时怎么办 | 编辑/重新生成/人工兜底 |
| 记忆能力 | Agent 是否记住用户偏好 | 短期记忆/长期记忆/可编辑 |

**交互原则**：
- **可控性**：用户始终掌握主动权，可打断、可修改、可撤回
- **透明度**：让用户理解 Agent 正在做什么、为什么这么做
- **渐进式呈现**：先给结论，再给推理过程，最后给详细信息
- **优雅降级**：模型能力不足时提供备选方案而非报错

### Phase 3: 效果评估体系

**评估维度**：

```
任务成功率
  ├── 用户发起 → Agent 理解正确 → 执行成功 → 用户满意
  └── 各环节漏斗转化率

效果指标
  ├── 客观指标：完成时间、操作步数、错误率
  ├── 主观指标：用户满意度(NPS)、净推荐值
  └── 质量指标：结果准确率、相关性、时效性

Badcase 管理
  ├── 回捞：通过日志和用户反馈发现 Badcase
  ├── 归类：按错误类型（理解错/执行错/输出错）分类
  ├── 定级：按影响范围和频次定优先级
  └── 闭环：修复后验证并更新测试集
```

### Phase 4: 持续迭代

**迭代节奏**：

| 阶段 | 周期 | 重点 |
|------|------|------|
| 冷启动 | 第 1-2 周 | 核心场景跑通，收集首批用户反馈 |
| 快速优化 | 第 3-6 周 | 集中修复 Badcase，提升成功率 |
| 体验打磨 | 第 7-12 周 | 交互细节优化，性能与稳定性 |
| 增长阶段 | 第 13+ 周 | 拓展场景，规模化运营 |

## 5. AI 产品经理的自我修养

### 5.1 持续学习方向
- **技术理解**：LLM 原理、RAG、Function Calling、多模态、Agent 框架
- **产品方法**：AI 产品评估方法论、用户行为分析、A/B 测试设计
- **动手实践**：用 API 搭 Demo、调 Prompt、写简单脚本验证想法

### 5.2 关键思维

```
❌ 这个功能 AI 能做 → 这是技术思维
✅ 这个场景用户是否需要 AI 来做 → 这是产品思维
✅ 用户用 AI 做的体验是否比原来好 10 倍 → 这是好产品的标准
```

### 5.3 避坑指南

| 常见问题 | 建议 |
|---------|------|
| 高估模型能力 | 先摸清模型边界，设计兜底方案 |
| 低估 Prompt 工程 | 好的产品体验 = 好的 Prompt + 好的交互 |
| AI 幻觉当 Bug 修 | 区分 "模型问题" 和 "产品问题"，分别治理 |
| 忽略首次体验 | 第一印象决定留存，首条回复质量至关重要 |
